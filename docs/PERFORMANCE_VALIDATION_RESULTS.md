# MK1Ai performance validation results

## Summary

**1.6 Tbps/node and 5 Pbps aggregate are not achieved or verified.** The repository
has no qualified physical high-speed NIC/fabric, 5 Pbps-class traffic generator
and receiver, or production-equivalent integrated data path. All local transport
results are synthetic TCP loopback diagnostics.

## Audit finding and correction

The prior paired node/fabric JSON scenarios sized both layers to meet the
target, so they demonstrated a `min(node, fabric)` bottleneck but did not prove
the evaluator handled arbitrary undersized installations. The calculator now
has a generic evaluator that accepts installed node/link counts, subtracts
exactly one failed item at each layer, applies the 80% factor once per
post-failure layer, and reports each layer's pass/fail and the limiting layer.
Tests cover node-only insufficient, fabric-only insufficient, both
insufficient, both sufficient, and tied capacities. This fixes a test-coverage
gap; it does not change the measured-performance status or assert a physical
topology.

## Latest benchmark-environment readiness check

On 2026-10-23, the current environment exposed only `lo`, virtualized `eth0`,
and `docker0`, with 2 online CPUs and approximately 7.8 GiB RAM. `lspci`,
`ethtool`, `iperf3`, `dpdk-testpmd`, and `trex-console` were unavailable.
This is an environment inventory, not a link-speed or throughput measurement.
No qualified NIC, calibrated generator/receiver, independent packet counters,
or target-scale fabric was available; therefore physical benchmark stages and
failure injection remain blocked, not failed or passed.

No C source changed, so C build checks were not rerun as part of this
documentation/calculator update. Skipped Python tests remain reported as
skipped; they are not treated as passed.

The 17 skips were 3 privileged nftables/network-namespace integration tests
(require root or `CAP_NET_ADMIN`, `iproute2`, `nftables`, and
`MK1_RUN_NETNS_TESTS=1`), 9 PyTorch-dependent model/training tests, 3 Google
Drive dependency tests, and 2 tests requiring both PyTorch and secure-transport
dependencies. The skipped integration tests do not validate physical
throughput; model/dependency skips also do not exercise the calculator changes.
No skipped test is counted as a pass.
